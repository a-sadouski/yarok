# Работа с проектом Yarok

## Контекст

Yarok — сайт с каталогом продукции и административной частью.
Frontend: Nuxt 4, Vue 3, TypeScript, Nuxt UI, Tailwind CSS.
Запросы /api/** проксируются на отдельный backend.

legacy-server/ содержит старую серверную реализацию.
Не используй её как источник актуального API-контракта
без проверки.

## Подход к задачам

- Перед изменениями изучи связанные файлы и существующие решения.
- Если задача неоднозначна, явно обозначь принятое предположение.
- Если неопределённость влияет на архитектуру или поведение
  продукта, сначала уточни её у пользователя.
- Ограничивай изменения поставленной задачей.
- Не добавляй зависимости без конкретной необходимости.
  Если зависимость нужна, объясни выбор.
- Сохраняй существующие изменения пользователя.

## Код

- Следуй принятым в соседних файлах соглашениям.
- Используй TypeScript; не добавляй any для обхода ошибок типов.
- Сосредотачивай обращения к API в app/api/.
- Не меняй API-контракты без проверки серверной реализации
  или согласованной спецификации.
- Не создавай абстракции без конкретного сценария использования.

## Пользовательское поведение

- Для асинхронных операций учитывай загрузку, успех,
  пустой результат и ошибку, когда эти состояния применимы.
- Сообщения об ошибках должны объяснять пользователю,
  что произошло и что можно сделать дальше.
- При изменении интерфейса учитывай мобильный экран,
  управление клавиатурой и подписи элементов формы.

## Проверки

Доступные команды:

- npm run lint
- npm run typecheck
- npm run build

- Выполняй проверки, относящиеся к изменению.
- Для изменений исходного кода запускай lint и typecheck.
- Для изменений конфигурации, зависимостей или поведения
  сборки дополнительно запускай build.
- Для исправления ошибки добавляй проверку, воспроизводящую
  её, если в проекте есть подходящая тестовая инфраструктура.
- Если проверку нельзя выполнить, сообщи причину.
- Отличай существующие ошибки от вызванных твоими изменениями.
- Не ослабляй проверки ради успешного результата.

## Границы действий

- Не публикуй секреты и содержимое .env в ответах и логах.
- Не выполняй деплой, миграции на удалённой базе или действия
  с production без явного поручения пользователя.
- Не редактируй генерируемые каталоги .nuxt/ и .output/.
- Не меняй legacy-server/, если задача явно его не затрагивает.

## Завершение задачи

В итоговом ответе укажи:

- Что изменилось и зачем.
- Как проверен результат.
- Какие ограничения или нерешённые вопросы остались.

Не объявляй задачу полностью завершённой, если её критерии
не выполнены или существенные проверки не прошли.
